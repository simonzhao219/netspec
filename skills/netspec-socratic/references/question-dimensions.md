# 追問維度框架（文字輸入 / Spec 生成）

LLM 每輪從以下維度挑選 2-3 個**尚未釐清**的問題，
優先選對 Spec 完整性影響最大的維度，不重複已問過的維度。

---

### 維度 1：業務目標與使用情境
- 這個功能解決什麼業務問題？目標用戶是誰？（網管人員 / NOC / 系統整合商 / 終端客戶）
- 這個功能是全新開發、還是取代/升級現有機制？
- 預計部署環境為何？（企業園區 / 資料中心 / 電信骨幹 / 分支辦公室）

### 維度 2：功能邊界與範圍
- 這個功能**不包含**什麼？有哪些相關功能明確排除在本次範圍外？
- 與哪些現有功能有相依性？（例如：需要先有 VLAN 才能做 QoS）
- 這次交付的是完整功能，還是 MVP / Phase 1 子集？

### 維度 3：效能與規模
- 預計同時操作的設備數量？最大部署規模？
- 有明確的 SLA 要求嗎？（延遲 < Xms、throughput > X Gbps、收斂時間 < Xs）
- 效能瓶頸預期在哪裡？（控制平面 / 資料平面 / 管理平面）

### 維度 4：高可用性與容錯
- 是否需要主備切換（Active/Standby）或負載分擔（ECMP/LAG）？
- 切換時間要求為何？允許多少秒的流量中斷？
- 設備重啟 / 軟體升級期間，服務是否需要不中斷？（NSR / NSF / Graceful Restart）

### 維度 5：安全與存取控制
- 這個功能是否涉及認證或授權？（AAA、Role-Based Access、API Token）
- 操作是否需要留存 audit log？保留多久？
- 是否有加密需求？（控制平面 / 管理通道 / 資料平面加密）

### 維度 6：錯誤處理與回滾
- 操作失敗時（設備離線、config 衝突、逾時），系統預期行為為何？
- 是否需要 rollback？rollback 的觸發條件與範圍為何？
- 批次操作中部分失敗時：全部取消、繼續其餘項目、還是人工介入？

### 維度 7：管理、監控與維運
- 這個功能需要哪些可觀測性指標？（計數器、錯誤率、狀態告警）
- 告警條件為何？透過什麼管道通知？（SNMP trap / Syslog / Webhook）
- 管理介面需求：CLI / NETCONF / RESTCONF / Web GUI，或以上皆要？

### 維度 8：相容性與標準
- 需要符合哪個版本的標準？（RFC 編號、IEEE 802.x）
- 必須相容的既有設備廠商或型號為何？
- 是否有互通性測試需求？（與他廠設備對接）

### 維度 9：邊界條件與協定限制
- 協定或欄位的數值邊界為何？（VLAN ID 1-4094、BGP AS 1-4294967295、MTU 限制）
- 硬體資源限制：TCAM 容量、路由表上限、連線數上限？
- 已知的競態條件（race condition）或協定衝突需要特別處理？

### 維度 10：驗收標準
- 這個功能如何驗證「完成」？驗收測試的場景是什麼？
- 驗收標準必須包含具體數字：
  ✅ 1000 台設備批次設定，完成時間 < 60 秒
  ✅ 主備切換，流量中斷 < 50ms
  ❌ 「系統應快速回應」（不可量測）
- 上線前需要通過哪些測試環境？（Lab / Staging / 壓力測試）
